## 48. Lazy Loading

> Defer off-screen images and heavy components until they are about to be seen or used. The native `loading="lazy"` attribute is free and needs no JavaScript; images are usually the largest part of a page's weight.

### Definition
Lazy loading postpones fetching or running a resource until it is likely to be needed: when it nears the viewport, when the user interacts, or when the browser is idle. Code splitting (principle 46) decides **how code is divided**; lazy loading decides **when each part is fetched**.

Three kinds of lazy loading matter on the web:
1. **Media**: images, iframes and video below the fold.
2. **Components and code**: heavy Client Components and libraries (`next/dynamic`, `import()`).
3. **Rendering work**: skipping layout and paint for off-screen content (`content-visibility: auto`) and virtualising long lists.

The risk is the same in all three: lazy-load the wrong thing (the hero image, the LCP element) and the page gets slower, not faster.

### Key properties

**1. Native lazy loading is zero-JS**
- `<img loading="lazy">` and `<iframe loading="lazy">` let the browser defer the request until the element nears the viewport. No observer code, no library.
- `next/image` renders `loading="lazy"` by default; you opt out for important images.

**2. Above-the-fold content must load eagerly**
- The LCP image, the logo and anything visible on first paint should not be lazy. Lazy-loading the LCP element delays it and hurts LCP (principle 8).
- In Next.js 16 mark such images with `preload` (the older `priority` prop is deprecated). The docs add that in most cases `loading="eager"` or `fetchPriority="high"` is enough; use `preload` when the image should start loading from the `<head>`, before it is discovered in the body.

**3. Reserve space to avoid layout shift**
- A lazy element without dimensions pushes content when it arrives. Give images `width` and `height` (or `fill` inside a sized container) and give lazy components a placeholder of the final size.

**4. Lazy components are loaded on demand**
- `next/dynamic` and `React.lazy` + `Suspense` load a component's chunk on first render. Combine with a condition (`open && <Dialog />`) so the chunk loads only when needed.

**5. Lists should be virtualised, not just lazy**
- A list of thousands of rows is a DOM and rendering problem; lazy-loading images in it does not fix it. Use virtualisation (`@tanstack/react-virtual`) or pagination.

### Decision table
| Resource | Technique | Zero JS? |
|---|---|---|
| Below-the-fold image | `<Image>` (lazy by default) or `loading="lazy"` | Yes |
| LCP / hero image | `<Image preload>` or `loading="eager"` + `fetchPriority="high"`; never lazy | Yes |
| Below-the-fold iframe (maps, embeds, video) | `loading="lazy"` on `<iframe>`; or a click-to-load facade | Yes |
| Video | `preload="none"` or `metadata` plus a poster; load on play | Yes |
| Heavy Client Component | `next/dynamic`, or `React.lazy` + `Suspense` | No |
| Library used on an event | `await import("lib")` in the handler | No |
| Section far below the fold | `content-visibility: auto` with `contain-intrinsic-size`; or Suspense streaming | Yes (CSS) |
| Custom reveal logic (infinite scroll, analytics on view) | `IntersectionObserver` | No |
| Very long list | Virtualisation (`@tanstack/react-virtual`) | No |

### Practical patterns in Next.js (TypeScript)

**Images: default lazy, hero eager**
```tsx
import Image from "next/image";

// Hero: visible on first paint, likely the LCP element
<Image src="/hero.jpg" alt="Product overview" width={1200} height={630} preload sizes="100vw" />

// Everything else: lazy by default, dimensions reserved
<Image src={card.cover} alt={card.title} width={640} height={360} sizes="(max-width: 768px) 100vw, 33vw" />
```
`next/image` defaults to `loading="lazy"`. For a plain `<img>` write `loading="lazy"` yourself and add `width` and `height`.

**Component: load on demand with a reserved box**
```tsx
"use client";
import dynamic from "next/dynamic";

const Chart = dynamic(() => import("./Chart"), {
  loading: () => <div className="h-64 animate-pulse rounded-md bg-muted" aria-hidden />,
});

export function UsagePanel() {
  return <Chart />;
}
```
`ssr: false` is only allowed in Client Components and only for code that truly cannot run on the server (a map or canvas). It is not allowed in Server Components.

**Load when it scrolls into view with `IntersectionObserver`**
```tsx
"use client";
import { useEffect, useRef, useState, type ReactNode } from "react";

export function WhenVisible({ children, minHeight = 256 }: { children: ReactNode; minHeight?: number }) {
  const ref = useRef<HTMLDivElement>(null);
  const [seen, setSeen] = useState(false);

  useEffect(() => {
    const el = ref.current;
    if (!el || seen) return;
    const io = new IntersectionObserver(
      ([entry]) => { if (entry.isIntersecting) { setSeen(true); io.disconnect(); } },
      { rootMargin: "200px" }, // start before it is on screen
    );
    io.observe(el);
    return () => io.disconnect();
  }, [seen]);

  return <div ref={ref} style={{ minHeight }}>{seen ? children : null}</div>;
}
```
Combine it with `next/dynamic` so both the render and the chunk wait for the viewport: `<WhenVisible><Chart /></WhenVisible>`.

**Stream slow sections instead of lazy-loading them on the client**
```tsx
// Server Component: the shell renders at once; the slow part streams in
<Suspense fallback={<RecommendationsSkeleton />}>
  <Recommendations />   {/* async Server Component */}
</Suspense>
```
For data-dependent sections below the fold, Suspense (principle 7) is usually better than client-side lazy loading: no client JS, and the HTML streams.

**Skip rendering of off-screen sections with CSS**
```tsx
<section className="[content-visibility:auto] [contain-intrinsic-size:auto_600px]">
  {/* long, expensive-to-lay-out content */}
</section>
```
`content-visibility: auto` lets the browser skip layout and paint for off-screen content. Always set `contain-intrinsic-size` so the scrollbar and layout stay stable.

**Lazy embeds with a facade**
```tsx
// Show a poster and load the heavy iframe only after a click
const [play, setPlay] = useState(false);
return play ? <iframe src={embedUrl} loading="lazy" title="Demo video" allow="fullscreen" />
            : <button onClick={() => setPlay(true)}><Image src={poster} alt="" width={640} height={360} /> Play</button>;
```

### Rules of thumb
1. **Eager above the fold, lazy below.** Never lazy-load the LCP element.
2. **Prefer the native attribute** (`loading="lazy"`) over a JS solution.
3. **Reserve space** (dimensions, aspect ratio or a fixed-size placeholder) for everything lazy.
4. **Load slightly early** (`rootMargin`, preload on hover) so users do not see the load.
5. **Lazy components only when heavy**: small components cost more in requests than they save.
6. **Stream with Suspense** for server data; lazy-load with `next/dynamic` for client-only code.
7. **Virtualise long lists** instead of lazy-loading each row.

### Anti-patterns
- `loading="lazy"` on the hero or any above-the-fold image, which delays LCP.
- Lazy images without `width` and `height`, causing layout shift.
- Lazy-loading dozens of tiny components, producing a request waterfall.
- A skeleton that is a different size than the final content.
- Re-implementing lazy images with scroll listeners instead of the native attribute or `IntersectionObserver`.
- `ssr: false` on content that matters for SEO or first paint.
- Lazy-loading content users reach with in-page anchors or find-in-page without a fallback.

### Industry best practices
- **Audit the LCP element** per key route (Lighthouse, field data) and make sure it is eager and preloaded.
- **Use `fetchPriority="high"`** on the LCP image and `fetchPriority="low"` on decorative below-the-fold images where it helps.
- **Set correct `sizes`** on responsive images so the browser downloads the right size (principle 49).
- **Use `loading="lazy"` on iframes**, and replace heavy embeds (video players, maps, chat widgets) with click-to-load facades.
- **Set `preload="none"` or `"metadata"`** on `<video>` and provide a `poster`.
- **Use `IntersectionObserver` with `rootMargin`** (for example 200px) to start work slightly before visibility; always disconnect the observer.
- **Honour data-saver and reduced-motion preferences** for non-essential media (`prefers-reduced-data` where supported, `prefers-reduced-motion`).
- **Wrap lazy parts in error boundaries and Suspense** (principle 19) so a failed chunk fetch shows a retry, not a blank area.
- **Pair `content-visibility: auto` with `contain-intrinsic-size`**, and test that in-page search and anchor links still work.
- **Measure with CLS, LCP and INP** (principle 8) on real devices; lazy loading that moves layout is a regression.
- **Lazy-load third-party scripts** with `next/script` (`lazyOnload`, `afterInteractive`) so they do not compete with first-party content.
- **Prefetch on intent** (hover, focus, `router.prefetch`) for the next likely navigation or component.

### Things to avoid
- Applying lazy loading to everything by default without checking what is above the fold.
- Using the deprecated `priority` prop in new Next.js 16 code; use `preload` (or `loading="eager"` / `fetchPriority="high"`).
- Using `preload` on many images; each competes for bandwidth, so reserve it for the one or two critical images.
- Hiding the loaded state behind a long fade-in that delays perceived content.
- Putting `IntersectionObserver` logic in every component; share one small hook or component.
- Relying on lazy loading to fix a page whose real problem is oversized images or too much JavaScript.
- Lazy-loading images inside a virtualised list as the only optimisation for huge lists.
- Forgetting `alt` text on lazy images.

### Checklist
- [ ] The LCP image on each key route is eager (`preload` or `loading="eager"` with `fetchPriority="high"`).
- [ ] Below-the-fold images and iframes are lazy; all have dimensions or a reserved box.
- [ ] Heavy components use `next/dynamic` or Suspense; small ones are not lazy.
- [ ] Skeletons and placeholders match the final size.
- [ ] Long lists are virtualised or paginated.
- [ ] Videos and embeds load on demand (`preload="none"`, facade).
- [ ] CLS and LCP were checked after the change.
