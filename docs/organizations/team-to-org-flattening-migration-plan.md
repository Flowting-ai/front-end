# Frontend Migration Plan — Team → Organization Flattening

Status: plan only, no frontend code changed yet.

## Background

Backend commit `1f82e241` ("Refactor project and persona services to use
organization_id instead of team_id", back-end repo) eliminates `Team` as an
entity. The hierarchy goes from `Org → Team → Project` to `Org → Project`.

Backend changes (60 files, migration `d4a1f7b93e26_flatten_teams_into_organizations.py`):

- `Team`, `TeamEditor`, `TeamViewer`, `TeamInvite`, `PersonaTeam` tables are
  **dropped**. The migration reparents every team-scoped fact onto the
  organization that owned the team.
- `Project.team_id` / `Chatboard.team_id` / `PersonaRepo.team_id` →
  `organization_id`. Visibility value `"team"` → `"org"`.
- Per-team editor/viewer grants are gone — access is now per-project via
  `ProjectMember` directly under the org.
- `TeamInvite` → `OrganizationInvite`; team-scoped connector/connection/
  persona-share endpoints move to `/organizations/{organization_id}/...`.
- Note: `back-end/openapi.yaml` is **stale** (not regenerated by this
  commit) — the diffs above come from reading the actual model/schema
  changes, not the spec.

## Frontend blast radius (as of this scan)

- Types: `Team`, `TeamMembership`, `TeamEditor`, `TeamInvite*`,
  `Chat.team_id`/`visibility:'team'`, `Project.team_id`/`teamId` — in
  `src/types/teams.ts`, `src/types/chat.ts`, `src/lib/api/projects.ts`
- `useOrg()` (`src/context/org-context.tsx`): exposes `teams`,
  `activeTeamId`, `removeTeam`, etc. — this subsystem has no backend home
  anymore
- `src/lib/api/teams.ts`: every function (`fetchTeams`, `createTeam`,
  `addTeamEditor`, `inviteTeamMembers`, team connectors/connections/
  persona-shares) hits endpoints that no longer exist as team-scoped
- ~53 files reference `teamId`/`team_id` across the sidebar
  (`TeamSwitcher*`), settings (`settings/teams/page.tsx` +
  `[teamId]/page.tsx`, 1300+ lines of team CRUD/editor-viewer UI),
  `InviteModal` (team picker + editor/viewer grant), project pages
  (`ProjectTeamPanel`, `ProjectMembersPanel`), and the `ChatShareOverlay`
  team-grouped project picker

Whole UI flows (team CRUD page, team detail/roster page, "make
editor/viewer" buttons, team-invite dropdown in `InviteModal`) have
literally nothing to call once this ships.

## Phase 1 — Data layer (types + API)

- `src/types/teams.ts`: retire `Team`, `TeamMembership`, `TeamEditor`,
  `TeamInvite*`, `TeamProject`, `SlackChannelMapping.teamId`, `TeamBurn`
- `src/types/chat.ts`: `Chat.team_id` → `organization_id`;
  `visibility: "private"|"team"` → `"private"|"org"`
- `src/lib/api/projects.ts`: `team_id`/`teamId` → `organization_id`/
  `organizationId` on `ProjectSummary`/`ProjectResponse`/`ApiProject*`/
  `CreateProjectParams`; visibility union updated
- `src/lib/api/teams.ts`: delete team CRUD/editor/invite/connector
  functions; keep only what maps onto surviving org-scoped endpoints
  (`ProjectMember` add/remove already exists here)
- `src/lib/config.ts`: swap `ORG_TEAM_*_ENDPOINT` constants for their
  `/organizations/{organization_id}/...` equivalents once the actual
  current paths are confirmed (openapi.yaml is stale — needs a live check
  against the backend, not just this diff)

## Phase 2 — `useOrg()` context

- `src/context/org-context.tsx`: drop `teams`, `teamsLoading`,
  `refreshTeams`, `removeTeam`, `activeTeamId`/`setActiveTeamId`
  (including its per-org localStorage persistence). Projects become a flat
  org-scoped list with no team grouping — this is the change with the
  widest downstream effect since nearly every consumer below reads
  `activeTeamId` or `teams`.

## Phase 3 — Components (in dependency order)

- Sidebar: `src/components/layout/LeftSidebar.tsx` (already merged
  personal/team project lists this session — now just drop the
  team-scoping filter entirely, not just merge), `src/components/
  TeamSwitcher/index.tsx`, `TeamSwitcherRow`, `TeamSwitcherDropdown` —
  likely deleted outright, no team to switch between
- `ProjectTeamPanel`, `ProjectMembersPanel`, `ProjectAgentsPanel` —
  collapse "team" concept out of project detail page
- `src/components/chat/ChatShareOverlay.tsx` — the team-grouped
  `Dropdown.Section` project picker built this session becomes a flat
  org-project list (no more grouping key)
- `src/components/InviteModal/index.tsx` — remove the team picker +
  `grantTeamEditor`/`grantTeamViewer` role branch; invite becomes org-role
  + optional direct project grant
- `src/context/projects-context.tsx` — `apiToProject`'s `teamId` fallback
  logic → `organizationId`

## Phase 4 — Delete now-orphaned pages/flows

- `src/app/(app)/settings/(shell)/(org)/teams/page.tsx` +
  `teams/[teamId]/page.tsx` (1300+ lines: roster, editor/viewer grants,
  team invites, team connectors) — no backend counterpart at all
- Duplicate legacy routes: `app/(app)/org/teams/*`,
  `app/(app)/teams/[teamId]/page.tsx`
- Onboarding: `app/(onboarding)/onboarding/team/[inviteId]/profile/
  page.tsx`, `context/team-invite-onboarding-context.tsx`
- `src/lib/team-access.ts` — check if logic still applies at org scope or
  is now dead
- `src/lib/team-gradients.ts` (shared helper added this session) likely
  survives as-is — gradients keyed by org, not team

## Phase 5 — Verify

- `npx tsc --noEmit` across the repo (expect a large error list initially
  — good, it's the map of every remaining touch point)
- Manual smoke test: sidebar, project creation/visibility toggle, chat
  share, invite flow, settings nav (teams entry removed from nav)

## Open question before Phase 1 can safely start

API paths for the surviving org-scoped endpoints (connectors, invites,
project members) aren't confirmed from the spec — only inferred from the
model/schema diffs. Worth confirming with the backend dev (or checking if
there's a newer spec/branch) before wiring real endpoint paths in
Phase 1.
