## 3. Thread A — Team → Organization flattening

The back-end already did this (five migrations, ending in `flatten_teams_into_organizations` — `Team`/`TeamEditor`/`TeamViewer`/`TeamInvite`/`PersonaTeam` tables dropped, everything reparented onto `Organization`). The front-end has an existing, detailed plan for this at `docs/organizations/team-to-org-flattening-migration-plan.md` — this thread absorbs it and adds one phase that plan didn't cover (the role ladder). Read that doc for full file-by-file detail; this section is the sequencing.

### Phase 1 — Data layer (types + API)
- `src/types/teams.ts`: retire `Team`, `TeamMembership`, `TeamEditor`, `TeamInvite*`, `TeamProject`, `SlackChannelMapping.teamId`, `TeamBurn`.
- `src/types/chat.ts`: `Chat.team_id` → `organization_id`; visibility `"private"|"team"` → `"private"|"org"`.
- `src/lib/api/projects.ts`: `team_id`/`teamId` → `organization_id`/`organizationId`.
- `src/lib/api/org-connectors.ts`: confirmed still team-scoped today — `teamIds`/`team_ids` fields on the connector-grant shape (lines 26, 41, 63). Same treatment as projects.ts.
- `src/lib/api/teams.ts`: delete team CRUD/editor/invite/connector functions; keep only what maps onto surviving org-scoped endpoints.
- `src/lib/config.ts`: swap `ORG_TEAM_*_ENDPOINT` constants for `/organizations/{organization_id}/...` equivalents — **confirm live paths with the backend dev first**, `openapi.yaml` is stale and wasn't regenerated by the flattening commit.

### Phase 2 — `useOrg()` context and the role ladder
- `src/context/org-context.tsx`: drop `teams`, `teamsLoading`, `refreshTeams`, `removeTeam`, `activeTeamId`/`setActiveTeamId` (incl. its per-org `localStorage` persistence, `activeTeamStorageKey`). Projects become a flat org-scoped list. This is the widest-blast-radius single change — nearly every consumer below reads `activeTeamId` or `teams`.
- **New finding, not in the original plan:** `src/lib/roles.ts` defines a 4-rung ladder, `Member → Editor → Admin → Owner`, where `Editor` is resolved from live `TeamEditor` grants — a table the backend already dropped. In practice this is **safe to collapse now**: `resolveRole()` has exactly one call site in the whole app (`org-context.tsx:289`), and it's always called with empty grants (`{ userId: user?.email ?? '' }`, no `editorTeamIds`/`projectIds` ever supplied) — so `Editor` is unreachable dead code today, not a live bug. Collapse the ladder to `Member → Admin → Owner` to match the backend's actual `services/organizations/roles.py`, and drop `Editor`, `RoleGrants.editorTeamIds`/`projectTeamIds`, `canEditTeam`, `canPublishToTeam`'s team-grant path. Re-home `canEditProject`/`canPublishToTeam` on the `ProjectMember`-based per-project checks the backend already uses instead of team grants.
- Update the stale comments in `roles.ts` ("mirrors `resolve_role()` on the backend") once the ladder actually matches again — they're actively misleading in their current form.

### Phase 3 — Components (dependency order)
- Sidebar: `LeftSidebar.tsx` — drop the team-scoping filter entirely (not just merge personal/team lists). `TeamSwitcher/index.tsx`, `TeamSwitcherRow`, `TeamSwitcherDropdown` — likely deleted outright.
- `ProjectTeamPanel`, `ProjectMembersPanel`, `ProjectAgentsPanel` — collapse "team" out of the project detail page.
- `ChatShareOverlay.tsx` — team-grouped project picker becomes a flat org-project list.
- `InviteModal/index.tsx` — remove the team picker and `grantTeamEditor`/`grantTeamViewer` branch; invite becomes org-role + optional direct project grant.
- `src/context/projects-context.tsx` — `apiToProject`'s `teamId` fallback → `organizationId`.

### Phase 4 — Delete now-orphaned pages/flows
- `settings/(shell)/(org)/teams/page.tsx` + `teams/[teamId]/page.tsx` (roster, editor/viewer grants, team invites, team connectors) — no backend counterpart at all.
- Duplicate legacy routes: `app/(app)/teams/[teamId]/page.tsx` (confirmed still present, same `isAdmin` pattern at line 598 as the real page).
- Onboarding: `onboarding/team/[inviteId]/...`, `context/team-invite-onboarding-context.tsx`.
- `src/lib/team-access.ts` — check whether the logic still applies at org scope or is dead.

### Phase 5 — Verify
- `npx tsc --noEmit` across the repo (expect a large initial error list — that's the map of every remaining touch point, not a regression).
- Manual smoke test: sidebar, project creation/visibility toggle, chat share, invite flow, settings nav (teams entry removed).

**Endpoint paths — confirmed directly from `services/organizations/router.py` (no backend-dev round-trip needed):** `/{organization_id}`, `/plan`, `/plan/pool-cap` (PATCH, Enterprise-only — see §6), `/plan/usage`, `/pool-status`, `/settings`, `/members`, `/members/admins`, `/members/regular`, `/members/{member_id}/role` (PATCH), `/members/{member_id}` (DELETE), `/connectors/{slug}/accounts`, `/audit`, plus several project-member and invite routes at lines 193-482 whose exact sub-paths weren't captured in this pass — read those directly before wiring `config.ts` Phase 1 rather than re-deriving from `openapi.yaml`, which is still stale.

- Credit-batch/rollover/expiry UI, Owner-set spend-cap control, top-up 20%-premium messaging, 8-tier Souvenir Core plan picker — the back-end has none of the batch/spend-cap model yet; there's nothing to wire against.
