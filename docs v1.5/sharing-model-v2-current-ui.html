DEAD END — CONFIRMED TWICE TODAY
Whatever gets picked here is permanent. There is no button, menu item, or endpoint anywhere that changes a project's visibility after creation — a live re-check of the entire /projects route table found nothing (the generic update endpoint's body schema doesn't even accept a visibility field). A Personal project stays Personal forever unless this gets built — this is the gap if the intended logic is "Personal now, Shared later, owner's choice."

The /projects list — scope filter

FIG 4 — real 3-way tab bar, rebuilt today from the old binary Personal/Team split Built

The old binary version had a real, live consequence: any org member's own Personal project also carries the org's teamId server-side, so a teamId-based filter miscounted it as a Team/Workspace project everywhere that reused the same shortcut — the sidebar's "Workspace projects" list, member-count badges on project cards, the Slack channel-linking picker, and the invite modal's "add to project" picker all did this independently. All rebuilt today to key off real visibility instead.

03Cross-cutting: dead code still in the tree

Three things confirmed unreachable or actively wrong today, none touched by today's Sharing-modal rebuild (each already tracked in the gap-audit doc):

  • Delete admin-bypass — project.canEdit || (isOrgAdmin && teamId===orgId) exists in three separate spots (two page-level gates plus one inside projects-context.tsx's deleteProject() itself) — the backend removed this bypass, so a non-owner admin clicking Delete gets a 404 every one of the three ways in.
  • Legacy Teams components — TeamSwitcher/TeamSwitcherDropdown/TeamChip are still live, still rendering, for a backend concept (Team) that's been fully dropped. Undecided: delete outright, or repurpose the shape for something else.
  • The old visibility-toggle modal's remnants — as of today, gone. It's the one item in this list that got resolved rather than just documented.

04The open question

STATED TARGET LOGIC, NOT YET BUILT ANYWHERE
A project is Personal or Workspace at creation. If Personal, the owner can later turn it Shared (and apparently back). Verified today, twice, that this has zero backing anywhere in the current backend — no endpoint, no schema field, no implicit side-effect of any existing action. Building it needs a new backend endpoint (something like owner-only, personal→shared, one-way or reversible) before the frontend has anything real to call. Halted pending a decision on that backend work.
