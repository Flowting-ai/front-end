Save & Publish

Save vs. Publish — the asymmetry every other tab inherits
  • Save: forks a brand-new version, stamps the URL with the new ?versionId=, removes persona_wizard_repo, clears the persona_instructions_draft_<repoId> sessionStorage draft, and — critically — sets localStorage persona_configure_saved_<repoId> = '1', which permanently unlocks Test Chat/AI Suggestions for this repo (see below).
  • Publish: updates the current version in place, sets it as published_version_id, removes persona_wizard_repo, clears persona_initial_version_<repoId>. Also unlocks the panels (published implies saved).
  • Auto-saves the draft to persona_instructions_draft_<repoId> continuously while typing — separate from either button, purely a browser-refresh safety net.

Floating panels & Help

Full panel content is detailed once in §06a below (identical shell on all 5 tabs). On this tab specifically:

  • Unlock condition: panelsLocked is true until localStorage persona_configure_saved_<repoId> is set or the repo has a published_version_id — the very first Save on any of the 5 tabs (not just here) flips this permanently for the repo.
  • Help panel (bottom-left ⓘ), Instructions' items: Model (optional), Agent Instruction (required — the only required field across all 5 tabs), Creativity Level/temperature (optional), Example Conversations (optional), plus static entries for Save Version and Publish themselves. Title badge reads "Required" (blue) here — every other tab's badge reads "Optional" (neutral).

  • Credit limit exhausted → 402 on accept → toast, no distinct state (preview shows credit_remaining but doesn't pre-block on it).
  • Not logged in → apiFetch's global 401 handling logs the user out and redirects to login with no returnTo back to the share URL — the recipient isn't guaranteed to land back on this page after signing in.
  • Recipient's email not on an email-type share's invite list, or already-accepted → both fall through to a generic "Something went wrong" error state; neither has a dedicated message.

Input

  • Opening "Add agent" calls fetchSelectableChatPersonas(), which filters to status !== 'draft' && visibility === 'private' — gap this still silently excludes every Workspace-visibility agent from the list, not just from a badge.
  • Copy-on-list, not copy-on-click: non-owned personas in that list are already cloned into the viewer's own account (via the same /use flow as the Library) by the time the dropdown renders — clicking one just attaches the already-resolved chip, no further clone happens.

Edge cases

  • Selecting a persona triggers getVersion() to populate systemPrompt; Send is blocked (personaConfigLoading) until that resolves.
  • If that fetch fails (e.g. the version was deleted or auto-evicted) it falls back to systemPrompt: '' plus an error toast instead of hanging Send forever — a previously-fixed bug, still the current behavior.
  • Removing the chip mid-compose clears persona state and unlocks the model selector. Switching personas mid-compose invalidates the previous in-flight getVersion fetch via a cancellation flag, so a stale response can't clobber the new selection.
