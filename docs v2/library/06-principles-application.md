# 06 Principles applied to Library (all 56, all 6 folders)

Source: `fe system design/principles/` (6 folders, 56 principles), `principles-tldr.md`, `base-primitive-rules.md`, and the audits in `fe system design/audits/` (cross-cutting gaps and the bundle-performance work). Every principle is classified **Apply**, **Apply narrowly**, or **Do not apply** with the reason, the concrete Library decision, and the checklist item it adds to the Definition of Done in `07-build-plan.md`. Decisions that change the earlier docs are marked **[changes 0X]** and were applied there.

Facts about this repo that drive the decisions (verified in code on 2026-10-13):
- Next.js 16 App Router, React 19, `reactCompiler: true`, webpack build (`next build --webpack`), React Query with one shared `QueryClient` (`staleTime` 30 s, `retry: 1`), zod 4, `sonner`, `@tanstack/react-virtual`, `@radix-ui/*`, `@base-ui/react`, `cva`. No zustand, redux, react-hook-form, nuqs, idb, jsdom, Testing Library, Playwright in `devDependencies`.
- Auth0 with the access token held in browser memory (`jwt-utils.ts`); same-origin streaming proxy `src/app/api/backend/[...path]/route.ts`; `directUpload()` bypasses the proxy for large bodies; `secureFetch` has rate limiters (api 100 req/min, upload 10 req/min, chat 30 req/min), a circuit breaker and a 5-request queue.
- CSP in `next.config.ts`: `img-src 'self' data: blob: https:`, `media-src 'self' blob:`, `connect-src 'self' <backend> <auth0> mixpanel ...`, `worker-src 'self' blob:`, no `frame-src` (falls to `default-src 'self'`).
- `perf-budget.json` + `scripts/perf-bundle.mjs` only budget **prerendered** pages; dynamic routes cannot be budgeted by them. `eslint.config.mjs` already blocks static imports of heavy packages.
- `agents/` has `error.tsx` (with `unstable_retry`) and `loading.tsx`; there is no `global-error.tsx`, no Sentry, no `useReportWebVitals`, no CI workflow except advisory `react-doctor.yml`, no `typecheck` script.

## Folder 1: Requirements and Rendering (principles 1 to 11)

| # | Principle | Verdict | Library decision | DoD item |
|---|---|---|---|---|
| 1 | Server Side Rendering | Apply narrowly | Pages are server **shells** only. No request-time data is fetched on the server because the access token lives in the browser and the app's data layer is client-side through the proxy. `page.tsx` files read **no** `cookies()`, `headers()` or `searchParams` (any one would make the route dynamic for no gain). The File page awaits `params` only to validate the id shape (`z.uuid()`), then `notFound()` for a malformed id. | `next build` route table shows Library routes as expected (`ƒ` for the dynamic segment, `○` for the list shell); no request API at page level |
| 2 | Client Side Rendering | **Apply (primary)** | The interior of every Library surface is a client island: table, tabs, search, filters, dialogs, upload, previews. `"use client"` sits on the leaves (`LibraryScreen`, `FileScreen`, `TrashScreen`, settings forms), never on `page.tsx` or `layout.tsx`. Data via React Query with abortable `signal`. Skeletons match final dimensions. | no `"use client"` on any `page.tsx`/`layout.tsx` in `app/(app)/library/**` |
| 3 | Static Site Generation | Do not apply | Per-user, permissioned data. Nothing to prerender. Do not add `force-static`. | none |
| 4 | Incremental Static Regeneration | Do not apply | Same reason, plus permissions and shares must never be cached shared. The ISR "tag" idea maps to React Query prefix invalidation. | none |
| 5 | Hybrid Rendering | **Apply (governing pattern)** | Per-route rendering table (below). Server shell + client interior everywhere. | rendering table kept current in `07-build-plan.md` |
| 6 | React Server Components | Apply | Static chrome (page title, empty-state copy) stays in server shells and is passed to client wrappers as `children`. Props crossing the boundary are serialisable and minimal (ids, not entities). The File page does **not** fetch the entity on the server. `import "server-only"` is not needed because no server data module exists. | review: every `"use client"` file states a reason in a one-line comment |
| 7 | Streaming SSR & Suspense | Apply narrowly | One `loading.tsx` per segment (instant shell). `useSearchParams` consumers sit under `<Suspense>` (a missing boundary fails `next build`). The File page streams nothing from the server; its slow side panels (Used in, Who has access) are separate client queries with their own skeletons (not Suspense popcorn per row). | `next build` passes with no missing-Suspense error |
| 8 | Core Web Vitals | **Apply (as UX budgets, not SEO)** | Targets on `/library` with a 5,000-row seed at 4x CPU, 10 Mbps / 40 ms RTT, median of 3: LCP <= 2.5 s, CLS <= 0.1, INP <= 200 ms (search and filter), TBT <= 300 ms. Reserve space for the storage label, Shared tab, toasts. Thumbnails in fixed boxes. Add a global `useReportWebVitals` once (shared prerequisite) plus custom marks for Library. | Playwright perf run (07 section 9) green |
| 9 | CDN & Edge Delivery | Apply narrowly | No edge runtime, no public caching of any Library response. Thumbnails and previews are `private`. Hashed chunks are already `immutable`. **The pdf.js worker must be a hashed asset** (import it with `new URL('pdfjs-dist/build/pdf.worker.min.mjs', import.meta.url)`), not the unhashed `public/pdf.worker.min.mjs`. **CSP additions are required** (below). | CSP change reviewed; worker URL hashed |
| 10 | Service Workers & Caching | Do not apply | Authenticated, per-user files are exactly what a service worker must not cache. No offline requirement. Revoke object URLs for local upload previews (`URL.revokeObjectURL`). | none |
| 11 | Progressive Web App | Do not apply | No manifest, no push. (A "file shared with you" push would need backend subscription storage, parked.) | none |

**Rendering table (principle 5)**

| Route | Server part | Client part | Data | Dynamic? |
|---|---|---|---|---|
| `/library` | static shell, title, `loading.tsx`, `error.tsx` | `LibraryScreen` (tabs, search, filters, table, Suggested) | React Query + URL params | list shell static |
| `/library/trash` | shell | `TrashScreen` | React Query | static shell |
| `/library/files/[fileId]` | validates `params.fileId` shape, `loading.tsx`, `error.tsx`, `not-found.tsx` | `FileScreen` (preview, info, access, dialogs) | React Query; `document.title` set client side after load with a sanitised name | dynamic segment |
| `/settings/library` | shell | `LibrarySettingsPage` | React Query | static shell |
| `/settings/library`, `/settings/workspace-library` | shell + Admin guard (existing `org/layout.tsx`) | forms and tables | React Query | static shell |

**CSP and platform changes this feature needs (add to `next.config.ts` and infra; call them out in the PR):**
1. `connect-src` += object-storage origin (resumable part PUTs and presigned GETs the viewers `fetch`).
2. `media-src` += object-storage origin (native `<audio>` plays a presigned URL; today `media-src` is `'self' blob:` and would block it).
3. `img-src` already allows `https:`; keep it, but prefer thumbnails through our own authenticated rendition endpoint.
4. No `frame-src`: **no iframes for previews** (principle 21).
5. `worker-src 'self' blob:` already covers the pdf.js worker.
6. Bucket CORS for the web origin (infra): `PUT`, `GET`, `HEAD`, exposed `ETag`.
Not changed: `proxyClientMaxBodySize` (320 MB) is irrelevant because part uploads go straight to storage.

## Folder 2: Architecture (principles 12 to 21)

| # | Principle | Verdict | Library decision | DoD item |
|---|---|---|---|---|
| 12 | Component Architecture | **Apply** | Feature folder `src/components/Library/` with colocated subfolders (`FileTable/`, `FilePreview/`, `ShareDialog/`, `TrashList/`, `Upload/`, `Settings/`) each with an `index.tsx` public export, private hooks and tests. `app/(app)/library/**` only assembles. Layers: `components/ui` (primitives) → Library composites → screens → routes; dependencies point down only. Build `FileTable` concretely; **no generic `<DataTable>`**. Rule of three before promoting anything to shared. Variants via `cva`; static class strings only (no `bg-${x}`). No component defined inside a component. | each component: one-sentence purpose without "and"; no component > 300 lines; props <= 7 or use slots |
| 13 | One-Way Data Flow | **Apply** | State ownership table in 07 section 4. Server data only in React Query. Tab, query, filters, sort, cursor in the URL. Selection in a local reducer. Upload queue in one external store. No copying props into state (the one documented exception is the share/rename dialog draft). Discriminated unions for statuses. | each piece of state names a single owner |
| 14 | Micro-Frontends | Do not apply | One app, one team. Library is a vertical feature folder. | none |
| 15 | Design System & Library | **Apply (reuse only)** | Reuse tokens and existing components. Add shadcn primitives through the `ui/` wrapper convention (precedent `ui/button.tsx`), restyled to semantic tokens. Library-specific parts (FormatGlyph, AccessAvatars, GeneratedMark) stay in `components/Library` until used three times. No raw hex, no primitive tokens in components; dark mode by token remap. Status and file-type use icon + text, never colour alone. z-index from tokens. | grep for raw colours in `components/Library` = 0 |
| 16 | Style Management | Apply | Tailwind + tokens is the approach. Dynamic values (upload %, column width, zoom) use CSS variables (`style={{"--progress": p}}`, `w-(--progress)`), not dynamic class names. Animate `transform` and `opacity` only. Honour `prefers-reduced-motion`, `forced-colors`, `:focus-visible`. A CSS Module only for a bespoke viewer (`PdfViewer.module.css`). No CSS-in-JS. Viewer-library CSS is scoped. | no `@apply` blocks, no arbitrary pixel values in table cells |
| 17 | Monorepo Structure | Do not apply | Single app. Keep layering clean so a future `packages/ui` extraction is cheap. Add an ESLint `no-restricted-imports` so `components/ui` cannot import Library and other features cannot deep-import `components/Library/*/internal`. | lint rule added |
| 18 | CI/CD for Frontend | **Apply** | Add `typecheck` script; gates on every Library PR: lint (incl. jsx-a11y), `tsc --noEmit`, vitest, `next build --webpack`, `perf:bundle:check`, Playwright smoke + axe on the preview deployment. Build once and promote (`NEXT_PUBLIC_*` is inlined at build). Flag `LIBRARY_ENABLED` has an owner and a removal date. Pin action versions, least-privilege permissions. | `.github/workflows/library.yml` (07 section 10) |
| 19 | Error Boundaries | **Apply** | `app/(app)/library/error.tsx` (mirrors `agents/error.tsx` and `AgentRouteError`), `[fileId]/error.tsx` so a preview failure keeps navigation, `not-found.tsx`, and **component-level boundaries around each previewer, the table region and the share dialog body**. A corrupt file never takes down the page; the fallback offers Download. Chunk-load failure inside a lazy preview shows Retry. Event handlers use try/catch + toast + report, and return typed `{ok:false, error}` for expected failures. Report the file **id only**, never the name. Depends on a one-time shared fix: existing `ErrorBoundary` only `console.error`s, and there is no `global-error.tsx`. | forced-throw test per boundary in a production build |
| 20 | Accessibility | **Apply (strict)** | WCAG 2.2 AA. File list is a real `<table>` with `th scope`, `aria-sort`, row `aria-rowindex`/`aria-rowcount` when virtualised, checkboxes labelled "Select <name>". Tabs, menus, dialogs from Radix/Base UI (focus trap and restore). Search result count in a polite live region. Upload start/end polite, failure `role="alert"` (not every percent). One `h1` per page, unique title. Preview: keyboard page nav/zoom, `alt` text, native audio controls with transcript, sheet as a table with header association. Targets >= 24x24 px. No colour-only status. | axe (wcag2a, wcag2aa, wcag22aa) clean on list and preview; manual NVDA/VoiceOver pass |
| 21 | Frontend Security | **Apply (highest risk area)** | Rules R1 to R10 in 07 section 8: file names are untrusted text only; previews never use `dangerouslySetInnerHTML`, inline SVG or iframes; sheet cells rendered as text and CSV export neutralises formula injection; presigned URLs short-lived, never persisted, never given our bearer token; every action authorised server side (UI hiding is not security); upload validation is UX only; no names or content in storage, analytics, logs or error reports. | security review sign-off; R1 to R10 tests |

## Folder 3: Component Patterns (principles 22 to 26)

| # | Principle | Verdict | Library decision | DoD item |
|---|---|---|---|---|
| 22 | Container / Presentation | **Apply** | The container is the **hook** (`useLibraryFiles`, `useLibraryFile`, `useLibraryUpload`, `useTrash`). A thin client container per screen calls hooks and hands prop-only views (`FileTable`, `FileRow`, `FilePreviewShell`, `SettingsToggleRow`, `PickerList`) a status union (`loading | error | empty | ready`) and intent-named callbacks (`onOpen`, `onShare`, `onRetry`). | 24 | Provider Pattern | Apply narrowly | Context only for low-frequency scoped values: picker config (multi-select, allowed formats, onConfirm) and the File page id. | 26 | Polymorphic Components | Apply | The name cell is a real `<Link href="/library/files/[id]">` via `asChild`/Slot. Never a clickable `div` with `router.push`. ## Folder 4: Data Model (principles 27 to 36)

| # | Principle | Verdict | Library decision | DoD item |
|---|---|---|---|---|
| 27 | Local State | **Apply** | `useState` for menu/dialog/hover/zoom/page/playhead/search draft. Selection as `Set<id>` in a reducer (ids, not objects). Upload item as a pure reducer with named transitions. Reset the viewer with `key={fileId}`. Derive, do not store (counts, filtered lists, isValid). | reducer tests |
| 28 | Global State (Zustand) | Apply narrowly | **One** shared high-frequency client state: the upload queue (read by the composer, the Library page and a progress tray). Implement as a small module store with `useSyncExternalStore` and per-upload-id selectors (the existing `active-chat-agent-store.ts` and `notifications/read-state.ts` precedent), **not** a new dependency. Revisit Zustand only if a second store appears. Never store server entities there. **[changes 02]** | store has selectors; no whole-store subscription |
| 29 | Redux vs MobX | Do not apply | No audit trail or undo requirement. | none |
| 30 | Server State (React Query) | **Apply (backbone)** | Key factory + `queryOptions`, `keepPreviousData` on filter/search changes, `useInfiniteQuery` for lists, deliberate `staleTime` per query (07 section 5), `signal` into every fetch, never retry 4xx, never `invalidateQueries()` without a key. | key factory covers every query |
| 31 | Data Normalisation | Apply | Files appear in list, detail, picker, trash and search and are edited, so: `detail(id)` is canonical; list and picker items are merge-seeded without downgrading richer fields; mutations write the returned entity then call one helper `patchFileEverywhere(qc, id, patch)` that is the only code touching several keys; prefix invalidation backs it up. No normalizr, no entity adapter. | unit test: partial list entity never overwrites a full detail entity |
| 32 | Cookies, LocalStorage, IndexedDB | Apply lightly | Only view prefs (view mode if a grid ever ships, column prefs, remembered sort) via a safe wrapper, keys added to `storage-keys.ts` (`library:v1:*`), cleared on logout. Never store files, names, presigned URLs, entities or settings. No IndexedDB. | keys centralised |
| 33 | Optimistic Updates | Apply (selective) | Optimistic with rollback: rename, trash (+ Undo toast), restore, revoke, settings toggles. **Never** optimistic: share (server resolves ways in), delete forever, Empty Trash, member removal/transfer, anything with a permission outcome. Sequence: `cancelQueries` -> snapshot -> write -> rollback on error -> `onSettled` invalidate; `mutationKey` + idempotent target-state PUTs; only the latest value sent for rapid toggles; failure path tested with a forced 500. `useOptimistic` is not used (no Server Actions). | failure-path tests |
| 34 | URL as State | **Apply** | One zod `libraryQuerySchema` with `.catch()` defaults shared by every consumer; `useLibraryQuery()` returns parsed params and `setParams(patch, "push" \| "replace")`. Search = debounced `replace`, tab = `push`, filters/sort = `replace` inside `startTransition`; reset cursor on any filter/sort change; omit defaults; `{scroll:false}`; Suspense around consumers. Picker state is local (transient). Identity is a path segment (`/library/files/[id]`), view is query. | round-trip test of the codec |
| 35 | Form State (RHF + Zod) | Apply (no RHF) | Forms are tiny (rename, share add, move, settings toggles). Plain controlled forms with shared zod 4 schemas (`z.email()`, `z.flattenError`), `safeParse` on submit, `aria-invalid` + `aria-describedby`, focus first invalid, disabled-while-pending. Adopt RHF only if share becomes a multi-recipient field array. Mirror backend limits (name length, size, types) as shared constants. | schemas tested |
| 36 | Real-Time State | Apply minimally | Processing status = polling via `refetchInterval` function (2 s for the first ~10 polls, then up to 10 s, `false` at terminal, no background polling) against a **batch** status endpoint (one request for all in-flight uploads, 04 section 5, otherwise ten uploads would exceed the 100 req/min limiter). Byte progress is client-side from the transport. No SSE/WebSocket for Library; chat SSE events that mention files patch or invalidate the Library cache by id. | poll cadence test |
